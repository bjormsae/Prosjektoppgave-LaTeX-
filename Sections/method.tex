\subsection{Starting point}
\label{sec:impl-start}
\begin{itemize}
    \item The AIS-IMM-PMBM implementation (2024, MIT licence): what it was built for (radar plus AIS, IMM), and what was kept (track trees, Murty, the update equations). About one page.
    \item What blocked scaling, with evidence: crashes beyond about 40 measurements per scan, and one global hypothesis list (the island experiment: 1.1 of 128 targets recalled, 91 of 128 with independent groups).
    \item From the old notes:
    \begin{itemize}
    \item Initial testing showed that the existing implementation would not scale up to the required size for real maritime surveillance. Clustering and gating needed to be implemented.
    \end{itemize}
\end{itemize}

The AIS-IMM-PMBM implementation was built to fuse AIS data with radar or lidar measurements. It also uses the IMM framework to better predict maneuvering vessels. We will drop both of these additions and use the bare PMBM filter in this project. AIS is dropped because it is used as ground truth in the measurement simulator and IMM is dropped for to simplify the system. Implementing an exact CT model prediction using N-vector would also have involved deriving these equations.
\medskip

The stock PMBM filter uses a HO-TO-hybrid formulation. Bernoullis form track trees and weights are cumulatively added down the tree. A global hypothesis is a list of references to Bernoulli leaf nodes in the track trees. At most one leaf node per track tree can be selected within a global hypothesis. The track tree depth is capped at $D_{max}$, so if the limit is reached, the children of the root node are removed and the grandchildren attached instead. Data association is handled by Murtys k-best assignment algorithm.
\medskip

While valuable as a working starting point, initial testing showed that the implementation would not scale very well. The PMBM was intended for small research examples, something which became apparent when the tracker crashed beyond about 40 measurements per scan. This was simply due to storing indexes as eight bit integers and thus easily fixable, but it nonetheless shows the intended scale of the implementation.

\subsection{n-vector integration}
\label{sec:impl-nvector}
\begin{itemize}
    \item Implemented in an equivalent direct form: each Gaussian (Bernoulli leaf, Poisson component) carries an anchor n-vector, the origin of its own North-East plane; the state is an offset in that plane. Why: the Kalman equations and the state layout stay unchanged.
    \item The innovation is the measurement in the anchor's plane minus $Hx$; after an update the anchor moves onto the posterior mean.
    \item Gaussian mixtures across planes: a new Bernoulli's moment matching (Section~\ref{sec:pmbm-update}) needs every gated Poisson component re-anchored into the measurement's plane first.
    \item Birth anchored at the centre of the field of view.
    \item Gating: one matrix product of all anchors against all measurements per scan discards far pairs, then the exact Mahalanobis test; the gated set equals brute force. The paper's cluster borders and measurement-to-measurement gate are not needed, because clusters are formed from the gated measurements.
    \item The single-plane baseline: the same tracker on measurements projected into one North-East plane at the centre of the field of view.
    \item Verification: unit tests against the nvector library and an exact spherical Monte Carlo.
    \item From the old notes:
    \begin{itemize}
    \item Added N-vector great circle prediction. 
    \end{itemize}
\end{itemize}

\subsection{Clustering}
\label{sec:impl-clustering}

Each cluster runs its own PMBM filter independently, with probabilities normalized within each cluster. As discussed earlier, there are two immediate benefits from using clustering for tracking. We don't need as many hypotheses per cluster and the association becomes far cheaper. The two operations concerning clusters are merging and splitting, where the latter is the difficult part. This section describes in detail how these two operations are implemented in the PMBM. 
\medskip

For this section we define the term group. It is a temporary entity, which exists only through the data association step. A group consists of all hypotheses which need to be considered in the same data association. Clusters become part of the same group if they gate the same measurement. A cluster gating a measurement means that at least one leaf node in a track tree gates the measurement. This effect is transitive, as seen in \autoref{fig:clustering_chaining}. A consequence is then that clusters nowhere near each other can be connected through intermediate clusters. Cluster borders being shown as ellipsoids in \autoref{fig:clustering_chaining} is a simplification, as it is actually the union of leaf node gates over all track trees part of the cluster.

\begin{figure}[htp]
    \centering
    \includegraphics[width=0.8\textwidth]{Images/fig11_chaining.pdf}
    \caption{Illustrative figure showing the formation of three groups: $G_1$, $G_2$ and $G_3$. Clusters are linked through gating the same measurements (solid black $X$), but also other gated measurements (gray $X$) must be part of the group.}
    \label{fig:clustering_chaining}
\end{figure}

\subsubsection{Merging}
Whenever multiple clusters enter the same group, they are merged. Conditioned on the previous cycle's gates, clusters are independent. This means that merging them is simply a Cartesian product over each cluster's hypotheses. Each cluster contains a list of global hypotheses and their respective weights. When clusters are merged, you simply multiply the weights (add the log weights) and make this a new global hypothesis with the combined leaf nodes from the track trees. Assuming each cluster has $H_{max}$ global hypotheses, the combined group has $H_{max}^k$ hypotheses, where $k$ is the number of clusters being merged. These are then pruned down to at most $H_{max}$ before running the association. Merging of multiple clusters is done one by one, and pruning is done after each cluster is merged. Thus, at most $H_{max}^2$ global hypotheses exist at one given moment. The merging of global hypotheses from two clusters is shown in \autoref{fig:clustering_merge}.

\begin{figure}[htp]
    \centering
    \includegraphics[width=0.8\textwidth]{Images/fig4_hypothesis_product.pdf}
    \caption{Merging of two clusters $A$ and $B$. $H_{max}$ is set to four, so only the four most likely combined hypotheses are kept. The weights are renormalized after capping.}
    \label{fig:clustering_merge}
\end{figure}

\subsubsection{Data association and reduction}
Prior to splitting, data association is performed, and some reductions are made to the posterior. This is done to only carry the most probable hypotheses forward, but also serves a second purpose. By removing low probability components, we reduce the chance of track entanglement, enabling more efficient cluster splitting. Including the association itself, four approximations are made:

\begin{enumerate}
    \item Murtys algorithm finds the most probable associations, capping the total hypotheses at $H_{max}$.
    \item Leaves which no hypotheses uses are removed. The resulting parent nodes without children are then removed recursively up to the root.
    \item Leaves with existence probability $r < 1^{-6}$ are also removed.
    \item The track tree depth is capped at $D_{max}$. The roots children are removed, attaching the grandchildren instead whenever the cap is reached.
\end{enumerate}

\subsubsection{Splitting}
After association, we are left with a single big group where unlikely posterior components have been removed. The goal is now to identify which tracks within the group are entangled and which ones are not. Tracks can then be formed into independent clusters by the same idea used in the merging (\autoref{fig:clustering_chaining}). 
\medskip

Just as with the merging, tracks are only entangled by measurement conflicts. The only difference is that we need to consider the entire measurement history when splitting. Each Bernoulli in the track tree is either tied to a measurement or a misdetection. A measurement is hashed by its location and timestamp such that a specific number can tell us if two Bernoullis have used the same measurement. This way, we can say that two track trees are entangled if any Bernoulli in track tree one uses the same measurement as a Bernoulli in track tree 2. Just as with merging, the reformation of clusters is also transitive, as seen in \autoref{fig:clustering_split}. The figure also captures how tracks can be connected without having recent measurement conflict.
\medskip

\begin{figure}[htp]
    \centering
    \includegraphics[width=0.8\textwidth]{Images/fig12_history_chaining.pdf}
    \caption{Three track trees connected by measurement history. All three go into the same cluster even though they don't all share a common measurement.}
    \label{fig:clustering_split}
\end{figure}

Two main reasons, make this cluster splitting scheme powerful. The first is that the splitting is exact given the previous reductions. No approximations happen in the splitting itself, meaning the splitting will be fair as long as the reductions are fair. This leads directly to the other strength of the splitting rule. The average cluster size and aggressiveness of cluster splitting is tunable, based on the approximations done before it. Specifically, adjusting the track tree depth can tune how long the tracker remember past measurement conflicts before considering them solved.
\medskip

To complete the reformation of clusters, the global hypotheses need to be marginalized over the new clusters. This is the inverse of the merging from earlier, and illustrated in \autoref{fig:clustering_split_hyp}. For simplicity, the figure only splits two independent tracks, but in general you just sum over tracks independent to each given cluster.

\begin{figure}[htp]
    \centering
    \includegraphics[width=0.5\textwidth]{Images/fig7_split_marginal_v2.pdf}
    \caption{Splitting the joint global hypotheses of two tracks $T_a$ and $T_b$ into independent hypotheses. Each cell in the matrix corresponds to a global hypothesis. Sum over the leaves of the independent track to obtain the marginal hypothesis.}
    \label{fig:clustering_split_hyp}
\end{figure}

\subsection{Recycling}
\label{sec:impl-recycling}
\begin{itemize}
    \item The special case implemented: a cluster with one track and one hypothesis whose Bernoulli has $r < 0.2$ becomes a Poisson component with weight $r$.
    \item Why: low-existence Bernoullis linked clusters into giant groups, and their evidence was lost in truncation.
    \item In practice almost all recycled Bernoullis are new ones born on clutter or on unconfirmed detections (98\,\% were never confirmed).
\end{itemize}

Capping, tree pruning, recycling.

\begin{itemize}
    \item Recycling is a non-trivial problem in general, but simple special case recycling can be implemented quite easily. 
    \item Criteria for being recycled; take a cluster with exactly one track and one hypothesis. The hypothesis's Bernoulli must also have existence probability $r < 0.2$. This component is then removed from the MBM and the posterior becomes a PPP component with $w = r$ and mean and covariance unchanged.
    \item The recycling does not lose any probability mass, it just moves it. We can therefore get away with such a high recycling probability threshold.
    \item The reason for recycling these components is mainly to allow for higher clutter scenarios without blowing up runtime. In a high clutter scenario without recycling, new Bernoulli components will quickly connect clusters and make the association step a bottleneck.
\end{itemize}

\subsection{Other changes}
\label{sec:impl-other}
\begin{itemize}
    \item Birth and survival per second instead of per scan: consistent when the scan interval varies.
    \item Exact assignment (linear sum assignment) inside Murty instead of the $\epsilon$-auction.
    \item Deterministic ordering of new Bernoullis: runs are reproducible bit for bit.
    \item The Poisson gate uses $S = HPH^{\mathsf{T}} + R$, as the Bernoulli gate does.
    \item Speed-ups that do not change results: one sentence, the list in Appendix~\ref{app:speedups}.
    \item From the old notes:
    \begin{itemize}
    \item Birth and survival rate are now per second. This is done for consistency and to allow for different measurement intervals.
    \item Multiple small bug fixes that either led to a speed-up or fixed crashes from scaling.
    \end{itemize}
\end{itemize}

\subsection{Estimation}
\label{sec:impl-estimation}
\begin{itemize}
    \item The best hypothesis of every cluster; their union is the best hypothesis overall. Bernoullis with $r > 0.5$ are reported.
    \item Estimates exist only at scan times; the history is stitched from per-scan best hypotheses, and not revised when the best hypothesis flips.
\end{itemize}
