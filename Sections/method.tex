\subsection{Starting point}
\label{sec:impl-start}
\begin{itemize}
    \item The AIS-IMM-PMBM implementation (2024, MIT licence): what it was built for (radar plus AIS, IMM), and what was kept (track trees, Murty, the update equations). About one page.
    \item What blocked scaling, with evidence: crashes beyond about 40 measurements per scan, and one global hypothesis list (the island experiment: 1.1 of 128 targets recalled, 91 of 128 with independent groups).
    \item From the old notes:
    \begin{itemize}
    \item Initial testing showed that the existing implementation would not scale up to the required size for real maritime surveillance. Clustering and gating needed to be implemented.
    \end{itemize}
\end{itemize}

The AIS-IMM-PMBM implementation was built to fuse AIS data with radar or lidar measurements. It also uses the IMM framework to better predict maneuvering vessels. We will drop both of these additions and use the bare PMBM filter in this project. AIS is dropped because it is used as ground truth in the measurement simulator and IMM is dropped for to simplify the system. Implementing an exact CT model prediction using N-vector would also have involved deriving these equations.
\medskip

The stock PMBM filter uses a HO-TO-hybrid formulation. Bernoullis form track trees and weights are cumulatively added down the tree. A global hypothesis is a list of references to Bernoulli leaf nodes in the track trees. At most one leaf node per track tree can be selected within a global hypothesis. The track tree depth is capped at $D_{max}$, so if the limit is reached, the children of the root node are removed and the grandchildren attached instead. Data association is handled by Murtys k-best assignment algorithm.
\medskip

While valuable as a working starting point, initial testing showed that the implementation would not scale very well. The PMBM was intended for small research examples, something which became apparent when the tracker crashed beyond about 40 measurements per scan. This was simply due to storing indexes as eight bit integers and thus easily fixable, but it nonetheless shows the intended scale of the implementation.

\subsection{n-vector integration}
\label{sec:impl-nvector}
\begin{itemize}
    \item Implemented in an equivalent direct form: each Gaussian (Bernoulli leaf, Poisson component) carries an anchor n-vector, the origin of its own North-East plane; the state is an offset in that plane. Why: the Kalman equations and the state layout stay unchanged.
    \item The innovation is the measurement in the anchor's plane minus $Hx$; after an update the anchor moves onto the posterior mean.
    \item Gaussian mixtures across planes: a new Bernoulli's moment matching (Section~\ref{sec:pmbm-update}) needs every gated Poisson component re-anchored into the measurement's plane first.
    \item Birth anchored at the centre of the field of view.
    \item Gating: one matrix product of all anchors against all measurements per scan discards far pairs, then the exact Mahalanobis test; the gated set equals brute force. The paper's cluster borders and measurement-to-measurement gate are not needed, because clusters are formed from the gated measurements.
    \item The single-plane baseline: the same tracker on measurements projected into one North-East plane at the centre of the field of view.
    \item Verification: unit tests against the nvector library and an exact spherical Monte Carlo.
    \item From the old notes:
    \begin{itemize}
    \item Added N-vector great circle prediction. 
    \end{itemize}
\end{itemize}

\subsection{Clustering}
\label{sec:impl-clustering}
\begin{itemize}
    \item The concrete rules: group clusters that gate a common Poisson-gated measurement; product of hypothesis lists, truncated; Murty and pruning per group; split by Kurien's rule.
    \item Approximations: truncation; conflicts older than the tree depth (10 scans) are forgotten.
    \item A split based on mutual information was tried and dropped: the truncation itself creates spurious dependence, so clusters never split.
    \item With everything in one cluster it reproduces the original tracker exactly (tested).
    \item From the old notes:
    \begin{itemize}
    \item Clustering merge: Whose children use the same Poisson-gated measurement form one group. The prior hypotheses are the product of their lists, truncated to the best N hypotheses,
    \item Clustering split: tracks whose surviving leaves' histories share no measurement go to separate clusters, each with the marginal of the hypothesis list (Kurien's MHT rule).
    \end{itemize}
\end{itemize}

Each cluster runs its own PMBM filter independently, with probabilities normalized within each cluster. There are two immediate benefits from using clustering for tracking. We don't need as many hypotheses per cluster and the association becomes far cheaper. 
\medskip

\paragraph{Merging}
Clusters are merged whenever they gate the same measurement. A cluster gating a measurement means that at least one leaf node in a track tree gates the measurement. Conditioned on the previous cycle's gates, clusters are independent. This means that merging them is simply a Cartesian product over each cluster's hypotheses. Each cluster contains a list of global hypotheses and their respective weights. Each global hypothesis points to at most one leaf node in each track tree. When clusters are merged, you simply multiply the weights (add the log weights) and make this a new global hypothesis with the combined leaf nodes from the track trees. Assuming each cluster has $H_{max}$ global hypotheses, the combined group has $H_{max}^k$ hypotheses, where $k$ is the number of clusters being merged. These are then pruned down to at most $H_{max}$ before running the association. Merging of multiple clusters is done one by one, and pruning is done after each cluster is merged. Thus, at most $H_{max}^2$ global hypotheses exist at one given moment.
\medskip

Every hypothesis that needs to be considered for data association is a group. This incudes the merged clusters and new Bernoullis. The group only exist as an entity through data association and is reformed into clusters after the association step.
\medskip

\paragraph{Splitting}
Splitting of clusters is not done explicitly. Rather, after data association is done, new clusters are formed based on measurement history. Each measurement is hashed by its timestamp and location, meaning each measurement is uniquely stored. 

\begin{itemize}
    \item Clusters only need to be rebuilt per group. Since groups don't share history with each other, they cannot form clusters across one another.
    \item Before splitting, four things happen. These are approximations, which makes the algorithm feasible, but they are small approximations if you think about it. After the association step we again keep at most the $H_{max}$ best hypotheses. We then remove leaves that no hypotheses uses, going upwards and removing parents with no children. We also remove every leaf with $r < 1^{-6}$ since it is very unlikely to exist. Finally, we cap the tree depth at $D_{max}$, removing the roots children and attaching the grandchildren instead.
    \item Clusters are reformed based on measurement history. If tracks contest the same measurement in the tree, they form a cluster. This procedure is a union over the group, meaning track $A$ and $B$ can be in the same cluster even though they don't share measurement history. This happens if both $A$ and $B$ share a measurement with another track $C$. 
    \item The maximum tree depth is what allows the splitting to work efficiently. 
\end{itemize}

\subsection{Recycling}
\label{sec:impl-recycling}
\begin{itemize}
    \item The special case implemented: a cluster with one track and one hypothesis whose Bernoulli has $r < 0.2$ becomes a Poisson component with weight $r$.
    \item Why: low-existence Bernoullis linked clusters into giant groups, and their evidence was lost in truncation.
    \item In practice almost all recycled Bernoullis are new ones born on clutter or on unconfirmed detections (98\,\% were never confirmed).
\end{itemize}

Capping, tree pruning, recycling.

\begin{itemize}
    \item Recycling is a non-trivial problem in general, but simple special case recycling can be implemented quite easily. 
    \item Criteria for being recycled; take a cluster with exactly one track and one hypothesis. The hypothesis's Bernoulli must also have existence probability $r < 0.2$. This component is then removed from the MBM and the posterior becomes a PPP component with $w = r$ and mean and covariance unchanged.
    \item The recycling does not lose any probability mass, it just moves it. We can therefore get away with such a high recycling probability threshold.
    \item The reason for recycling these components is mainly to allow for higher clutter scenarios without blowing up runtime. In a high clutter scenario without recycling, new Bernoulli components will quickly connect clusters and make the association step a bottleneck.
\end{itemize}

\subsection{Other changes}
\label{sec:impl-other}
\begin{itemize}
    \item Birth and survival per second instead of per scan: consistent when the scan interval varies.
    \item Exact assignment (linear sum assignment) inside Murty instead of the $\epsilon$-auction.
    \item Deterministic ordering of new Bernoullis: runs are reproducible bit for bit.
    \item The Poisson gate uses $S = HPH^{\mathsf{T}} + R$, as the Bernoulli gate does.
    \item Speed-ups that do not change results: one sentence, the list in Appendix~\ref{app:speedups}.
    \item From the old notes:
    \begin{itemize}
    \item Birth and survival rate are now per second. This is done for consistency and to allow for different measurement intervals.
    \item Multiple small bug fixes that either led to a speed-up or fixed crashes from scaling.
    \end{itemize}
\end{itemize}

\subsection{Estimation}
\label{sec:impl-estimation}
\begin{itemize}
    \item The best hypothesis of every cluster; their union is the best hypothesis overall. Bernoullis with $r > 0.5$ are reported.
    \item Estimates exist only at scan times; the history is stitched from per-scan best hypotheses, and not revised when the best hypothesis flips.
\end{itemize}
